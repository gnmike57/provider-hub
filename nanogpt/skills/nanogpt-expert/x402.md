# x402 accountless payments (distilled)

> Full verbatim source: `sources/docs/api-reference__miscellaneous__x402.md`.
> Live-observed headers: `live-verification.md`. Matrix: `sources/manifests/x402-endpoints.json`.

**Core flow:** send the request with **no** `Authorization`/`x-api-key` and header `x-x402: true` ->
`402 Payment Required` with a payment quote -> pay -> complete/replay. Without `x-x402: true` an
unauthenticated request returns `401 missing_api_key` (no quote generated).

## Accountless endpoint matrix (stable scope)
| Endpoint | Scope | Quote |
|---|---|---|
| `POST /api/v1/images/generations` | JSON | deterministic |
| `POST /api/v1/images/edits` | JSON (multipart needs auth first) | deterministic |
| `POST /api/v1/chat/completions` | **non-streaming** | estimated + reconciliation |
| `POST /api/v1/responses` | **non-streaming** | estimated + reconciliation |
| `POST /api/v1/data/web/search` | JSON | deterministic |
| `POST /api/v1/data/url/scrape` | JSON (`urls: [...]`) | deterministic |

Source of truth: `GET /api/v1/x402/endpoints` (`?supported=all` for beta/deferred). Only endpoints
returning a valid 402 quote in smoke tests are supported. Streaming chat and long-running video are
**not** the stable accountless contract.

## Payment schemes (docs table)
| Scheme | Network | Asset | Flow |
|---|---|---|---|
| `nano` | nano-mainnet | XNO | send XNO to unique address -> `completeUrl` |
| `nano-exact` | Nano exact | XNO | sign exact payload -> replay with `X-PAYMENT` |
| `base-usdc` | Base | USDC | send USDC -> `completeUrl` |
| `x402-exact` | Base | USDC | EIP-3009 auth in `X-PAYMENT` -> replay |
| `x402-solana-usdc` | Solana/SVM | USDC | Solana exact payment in `X-PAYMENT` -> replay |
| `lightning-l402` | bitcoin-lightning | sats | pay invoice -> replay with `Authorization: L402 <token>:<preimage>` |

Solana USDT and native SOL are **not** documented rails. Live scheme names differ from this table -
see `live-verification.md`; trust `GET /api/v1/x402/endpoints` and the live `x-payment-schemes` header.

## Three settlement flows
1. **Quote, Pay, Complete** (`nano`, `base-usdc`): pay to the quoted address, then call the quoted
   `completeUrl`. Key off the top-level `payment` object (the `error` object is OpenAI-compat only).
2. **Exact replay** (`nano-exact`, `x402-exact`, `x402-solana-usdc`): sign the exact requirement and
   replay the original endpoint with `X-PAYMENT: $BASE64_PAYMENT_PAYLOAD`. Success includes
   `X-PAYMENT-RESPONSE` when a settlement hash exists.
3. **Lightning L402 replay** (`lightning-l402`): pay the invoice, replay with
   `Authorization: L402 <token>:<preimage>`.

## Status polling
For `nano`/`base-usdc`, poll the quoted `statusUrl` (`/api/x402/status/pay_...`).
Statuses: `pending`, `underpaid`, `paid`, `processing`, `completed`, `failed`, `refunded`, `expired`.
Responses include `pollAfterSeconds`, `Retry-After`, `X-Poll-After`.
Complete endpoint: `POST /api/x402/complete/{paymentId}`.

## Reconciliation
- Image + data quotes are **deterministic** for the submitted params.
- Chat/Responses quotes are **estimates**, reconciled after provider usage; if execution fails after
  settlement, the endpoint attempts documented refund/failed-fee reconciliation.
- `completeUrl` replays the stored original request (bound to method, path, body).
- Exact `X-PAYMENT` and Lightning L402 are validated against the quoted resource/amount/expiration.

## Safety notes
- `completeUrl`/`X-PAYMENT`/L402 are bound to method, path, body hash, amount, expiration.
- `Authorization: L402 <token>:<preimage>` is bearer payment proof - **do not log it**; nor `X-PAYMENT`.
- Expired / underpaid payments **cannot** be completed. Completed/processing cannot be completed twice.
- Store the original request only as long as needed for completion.
